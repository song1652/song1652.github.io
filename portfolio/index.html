에버엑스 · PM·QA

Flexum

기획의 의도를 검증 기준으로 연결하고, 결과지 생성까지 확인했습니다.

품질 과제
Android 셋톱박스에서 동작하는 근골격계 분석 소프트웨어의 기획·개발관리와 QA를 함께 맡았습니다. 검사 결과지 생성 과정과 실기기에서 간헐적으로 발생하는 크래시를 함께 검증해야 했습니다.
주요 기여

스쿼드 조직 관리와 기획·개발 조율. 스쿼드 운영과 개발관리를 맡고, 요구사항·사용자 만족도 조사를 바탕으로 업데이트 우선순위와 개발 일정을 조율했습니다. PRD·Figma의 기능 의도와 사용자 흐름을 TC 설계에 반영해 기획과 검증의 기준을 맞췄습니다.

간헐적 실기기 이슈를 로그로 분석. Android 셋톱박스를 노트북에 연결하고, AI를 보조 도구로 활용해 이슈가 발생할 때까지 실행을 반복했습니다. 크래시 발생 시점의 Logcat을 추출·확인하고 로그 근거를 개발팀에 공유했습니다.

AI 초안을 실제 제품 검증으로 연결. Figma MCP로 TC 초안을 작성하도록 구성했습니다. 문서만으로 확인하기 어려운 제품 로직과 결과지 생성 과정은 직접 검토해, 실제 검증에 사용할 항목으로 보완했습니다.

결과
Flexum은 의료기기 2등급 인증을 받았고 KMI 건강검진센터의 기본 검진 항목에 채택됐습니다.

에버엑스 · 회귀 자동화

MORA RTM / REHAB

중복되는 회귀 검증을 코드로 묶어, 출시 대응과 신규 기능 QA를 병행했습니다.

품질 과제
기존 제품과 화이트라벨 버전에 같은 처방 기능이 있었습니다. 새 기능을 검증하는 동안에도 두 버전에서 기존 동작을 반복해서 확인해야 했습니다.
주요 기여

화면과 데이터로 검증 근거 확보. API 응답 건수·화면 표시 건수·실제 목록 수를 대조하고, 불일치하면 비교값을 오류 메시지에 남겼습니다. Swagger·Postman으로 테스트 데이터를 직접 생성해 검증에 활용하고, 환자 데이터의 적합성도 확인했습니다.

반복 실행할 수 있는 회귀 절차 구성. Python·Selenium·pytest로 공통 검증 코드를 직접 작성하고 실행 환경과 사용법을 팀에 공유했습니다. AI는 코드 리뷰를 보조하는 데 활용했습니다.

결과
회귀 테스트 자동화를 처음 도입했습니다. 화이트라벨 제품은 고객사에 성공적으로 납품됐으며, 자사 제품은 미국·싱가포르 등 해외 시장에서 운영되고 있습니다.

에버엑스 · 기획 단계부터 참여한 임상 QA

MORA Cure

기획 단계부터 참여해 검증 범위를 정하고, 기능·환자 데이터·임상 산출물을 함께 관리했습니다.

품질 과제
기획 단계부터 임상 검증용 웹·앱의 QA를 맡았습니다. 제품의 요구사항을 테스트 계획과 검증 조건으로 구체화하고, 환자 데이터의 정상 노출과 기능 동작을 확인할 근거를 갖춰야 했습니다.
주요 기여

기획 단계의 검증 범위·계획 수립. 개발 스쿼드와 테스트 환경·로드맵을 협의하고, 테스트 계획과 웹·앱 TC를 설계했습니다.

기능과 환자 데이터의 적합성 검증. 모바일 실기기에서 동작을 확인하고, Swagger를 활용해 데이터 적합성을 검증했습니다. 환자 데이터가 주차별로 정상 노출되는지도 확인했습니다.

임상 검증 산출물 관리. 규제 요구사항을 테스트 조건과 산출물에 반영하고, 이후 임상 문서 재제출·보완에도 대응했습니다.

결과
MORA Cure 프로젝트가 임상 승인을 획득했습니다.

셀렉트스타 · SaaS 기능·성능 검증

DATUMO

기능의 정상 동작과 대량 데이터 처리 규모를 함께 확인했습니다.

품질 과제
기업용 데이터 관리 SaaS의 상용화를 위한 QA를 맡았습니다. 웹 기능의 정상 동작과 함께 대량 데이터를 올릴 때 서비스가 감당할 수 있는 규모를 확인해야 했습니다.
주요 기여

상용화를 위한 기능 검증. 웹 기능별 TC를 설계·실행하고, 대량 업로드는 데이터 규모를 바꿔가며 실제 처리 결과를 확인했습니다.

개발팀과 처리 범위 교차 확인. 백엔드 개발자와 수십만 건의 데이터를 업로드해 최대 처리 규모와 적정 규모를 구분했습니다. 화면의 정상 동작만으로 판단하기 어려운 성능 범위를 실제 데이터로 확인했습니다.

결과
DATUMO는 10개 이상의 대기업 고객사에 납품됐습니다.

셀렉트스타 · 플랫폼 통합·회귀 검증

캐시미션

개별 기능부터 채널 간 연결까지, 전 플랫폼의 검증 범위를 정리했습니다.

품질 과제
데이터 가공 크라우드소싱 플랫폼에서 웹·앱·어드민 QA를 전담했습니다. 각 채널의 기능과 변경이 반영된 뒤의 통합 동작을 함께 검증해야 했습니다.
주요 기여

채널을 연결한 기능·통합·회귀 검증. Web·Android·iOS·Admin을 함께 확인하고, 변경 후 영향을 검토했습니다. 발견한 결함을 분석해 검증 항목의 우선순위를 정했습니다.

팀이 함께 검증하는 기준 마련. QA가 1명에서 2명으로 늘면서 채널별 범위와 담당을 나눴습니다. 공통으로 사용할 테스트 환경을 정리해 개인의 확인을 팀 단위 검증으로 확장했습니다.

결과
빠른 릴리즈 주기에도 검증 근거를 전달하고, 재사용 가능한 문서와 테스트 환경을 구축해 팀의 QA 환경을 표준화했습니다.

에버엑스

다제품 QA를 위한 역할·기준 정립

QA 2명이 3개 제품을 병행 검증하는 환경에서 스쿼드별 테스트 전략을 수립하고, 개발팀과 검증 범위·일정을 조율했습니다. 팀이 4명으로 확대되는 과정에서는 제품별 역할을 나누고 공통 TC 작성·관리 기준을 정립했습니다.

업무 절차를 온보딩 문서로 정리하고, 테스트 리포트와 자동화 코드·검증 사례를 공유해 팀원이 같은 기준으로 검증할 수 있도록 했습니다.

테스트 데이터 준비 과정 개선

개발자에게 요청하거나 스크립트를 수정해야 했던 데이터 준비 과정을 개선했습니다. QA가 조건을 입력하면 테스트 데이터를 생성·검증할 수 있는 CLI 도구를 직접 개발했습니다.

QA가 코드를 수정하지 않고도 필요한 시점에 테스트 데이터를 직접 준비할 수 있게 했습니다.

QA Lead · 2020.10–2023.04

셀렉트스타

스프린트 기반 배포·검증 체계 정립

개발팀의 자체 테스트가 끝나면 비정기적으로 배포하던 방식에서, 개발 리더들과 협의해 스프린트 기반의 개발·배포 체계로 전환했습니다.

정해진 배포 주기에 맞춰 QA 일정을 계획하고, 단계별 검증 절차와 산출물을 정의해 적용했습니다.

반복 이슈를 반영한 QA 절차 개선

반복해서 발생하는 이슈를 분석하고, 다음 검증에서 확인할 항목과 QA 절차에 반영했습니다. 캐시미션 QA가 1명에서 2명으로 확대될 때는 플랫폼별 업무 분배와 검증 우선순위 기준도 정리했습니다.
